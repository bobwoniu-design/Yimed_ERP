# 独立内容中心

状态：开发环境已完成破坏性重置  
确认日期：2026-08-18

## 最终定位

内容中心是独立的企业文件库，不再作为 ERPNext 业务附件系统，也不按公司隔离。
ERPNext 的物料、采购、销售、库存、生产、质量等业务单据继续使用原生附件。
内容中心文件不会自动出现在业务单据附件区，业务单据附件也不会自动进入内容中心。

## 保留能力

- 全局多级文件夹与可折叠目录树；
- 按角色或用户设置文件夹 ACL，并由最近祖先目录向下继承；
- 私有文件上传、受控预览、下载和缩略图；
- 文件版本、标题、备注、负责人、部门、到期日和锁定；
- 标签、星级、收藏、最近使用、筛选和多种列表/缩略图视图；
- 批量移动、复制、下载、回收、恢复和彻底删除；
- 操作审计与内容健康检查。

## 已彻底移除

- 文件夹和内容资产的公司字段及公司切换界面；
- 集团视图、批次公司归属、跨公司文件授权；
- 内容中心与 ERPNext 业务记录的关系表及表单入口；
- 业务附件目录配置、归档模板、ERP 原生附件归档和附件同步；
- 旧版复杂批次报告、报告要求、报告类型、审批、有效期及多报告关系。

上述旧 DocType、数据库表和开发期历史数据均已删除，不做旧数据迁移。

## 权限原则

- `Content Center Manager` 和系统管理员可以管理全局根目录、子目录与 ACL；
- `Content Center User` 只获得根目录基础查看/下载能力，其他写权限由目录 ACL 明确授予；
- ACL 授权对象只有角色或用户，不检查 Company；
- 每次查询、预览、下载、上传、移动和删除均在服务端重新校验目录权限；
- 私有物理文件继续存放在 Frappe `File`，但只能通过内容中心受控接口访问。

## 批次检测报告（独立功能）

批次检测报告不属于内容中心数据模型：

- 字段位于 ERPNext `Batch.custom_inspection_report_attachment`，标签为“检测报告附件”；
- 每个 Batch 只维护一个当前私有 PDF、PNG、JPG 或 JPEG；
- 具有 Batch 读取权限的系统用户可以查看、上传、替换、删除和下载；
- 替换报告不保留旧版本，旧的本工作流文件会永久删除；
- Delivery Note 的“导出 → 批次检测报告”生成“出库单号-检测报告.zip”，每个批次报告保持原文件名并单独存放；同名时才追加序号防止覆盖；
- 缺失报告在导出前提示，但不阻断其余报告进入压缩包；
- 内容中心重置不会删除 Batch 检测报告的 `File` 和物理文件。

## 数据模型

- `Channel Content Folder`：全局文件夹树；
- `Channel Content Folder Access`：角色/用户 ACL；
- `Channel Content Asset`：逻辑文件和当前状态；
- `Channel Content Asset Version`：不可变文件版本，引用私有 Frappe `File`；
- 收藏、访问日志、标签索引和审计日志：内容中心内部辅助记录。

不存在 Company 字段、业务关系表或业务附件映射表。

## 验收标准

1. 打开内容中心只显示“企业文件”全局根目录，不出现当前公司、集团或跨公司设置；
2. 文件夹权限仅支持角色和用户，继承和服务端拒绝行为正确；
3. 私有文件可完成上传、详情、预览、锁定/解锁和永久删除全生命周期；
4. 删除内容资产时同时删除其自有 `File` 与物理文件；
5. ERPNext 原生业务附件无任何内容中心脚本或同步逻辑；
6. Batch 检测报告附件及 Delivery Note 合并导出独立可用；
7. 所有旧公司/集团/业务关系 DocType、数据库表与数据均不存在；
8. 不修改 Frappe 或 ERPNext 核心代码，后续升级只同步 `channel_erp` 自有模型与脚本。
